# GameTrack — клиент (Angular 20)

Одностраничное приложение для ведения личной коллекции видеоигр. Работает с реальным
backend-ом `GameTrack.Api` (ASP.NET Core Web API) по REST — моки удалены полностью.

Весь интерфейс — на русском языке. Тёмная игровая тема: фон `#041629`, карточки
`#071F35` / `#0B2944`, акцент `#4C45FF`. Иконки — один набор **PrimeIcons**.

---

## Что реализовано

### Аутентификация
- Вход (`/auth/login`) через `POST /api/auth/login` с демо-данными
  `demo@gametrack.app` / `demo1234`.
- Регистрация (`/auth/register`) через `POST /api/auth/register`: имя, email, пароль
  и подтверждение пароля. После успешной регистрации сессия создаётся сразу.
- Восстановление пароля (`/auth/recovery`) через `POST /api/auth/recovery`.
- Сессия сохраняется в `localStorage` (`gametrack.session.v3`) и восстанавливается после
  перезагрузки. Выход — из меню профиля в шапке.
- У каждого аккаунта отдельная библиотека игр. Идентификатор аккаунта передаётся в API
  заголовком `X-User-Id` через HTTP-интерцептор.
- Маршрутизация защищена: `authGuard` не пускает гостя в приложение (редирект на вход с
  `redirect`), `guestGuard` не пускает вошедшего пользователя на страницы входа и регистрации.

### Дашборд (`/dashboard`)
- Приветствие по имени, краткая сводка (всего игр, в процессе, пройдено, хочу пройти),
  список недавних игр со ссылкой на полный список.

### Библиотека игр (`/games`)
- Поиск на сервере (`search`) и фильтр по статусу (`status`).
- Серверная пагинация: 6 игр на страницу, переходы «назад/вперёд», счётчик найденных игр
  и состояние «ничего не найдено».

### Карточка игры (`/games/:id`)
- Обложка, год выпуска, рейтинг, жанр, платформа, дата добавления, описание.
- Смена статуса через `PATCH /api/games/{id}/status`, кнопка-переключатель
  «в список желаемого / убрать из желаемого», кнопка «Отметить как пройденную».
- Удаление с подтверждением (диалог) и состояние «Игра не найдена» для некорректной ссылки.

### Добавление и редактирование (`/games/new`, `/games/:id/edit`)
- Валидируемая форма: название (уникальное), жанр, платформа, статус, год, рейтинг, описание.
- Загрузка обложки (файл изображения), превью, подстановка плейсхолдера при отсутствии картинки.

### Список желаемого (`/wishlist`)
- Загружается с сервера отдельной пачкой игр со статусом `want-to-play`.
- Быстрые действия по каждой игре.

### Статистика (`/statistics`)
- Всего / пройдено / в процессе / хочу пройти / брошено, доля пройденных, средний рейтинг.
- Распределение по статусам, жанрам и платформам — рассчитывается на backend-е
  (`GET /api/statistics`) и обновляется после изменений библиотеки.

### Профиль (`/profile`)
- Просмотр и редактирование имени, email, аватара через `GET/PUT /api/profile`.
- Изменения сразу отражаются в шапке и на всех экранах (единый источник состояния — сигналы).

### Общее
- Уведомления-тосты о результате действий.
- Адаптивная вёрстка: на узких экранах боковое меню превращается в выдвижную панель
  (кнопка-гамбургер), проверено на ширине 390 px.
- Понятные сообщения об ошибках API (`ApiError` / `toApiError`).

## Архитектура

```
src/app
├── core/
│   ├── auth/           хранение сессии (localStorage)
│   ├── config/         конфигурация приложения и маршрутов (lazy-loading)
│   ├── http/           ApiError, преобразование ошибок и X-User-Id интерцептор
│   ├── navigation/     guards: authGuard / guestGuard
│   └── services/       GamesService, StatisticsService, AuthService,
│                       ProfileService, ImageStoreService (IndexedDB)
├── environments/       environment.ts / environment.development.ts (apiUrl)
├── shared/             переиспользуемый слой
│   ├── components/     game-card, cover-image, status-pill, confirm-dialog,
│   │                   empty-state, toast-host
│   ├── models/ constants/ utils/ validators/
│   └── notifications/  сервис тостов
├── layout/             app-shell (сайдбар + шапка), guest-shell, not-found, app-root
└── features/           страницы по фичам: auth, dashboard, games, wishlist,
                        statistics, profile — каждая со своими *.routes.ts
```

Ключевые решения:
- **Standalone-компоненты** + Angular Router, строгий TypeScript (`strict`), SCSS,
  lazy-loaded маршруты фич.
- **Signals** как единый источник истины: сервисы хранят состояние в сигналах, все экраны
  обновляются реактивно.
- Все запросы идут через `HttpClient`, каждый вызов продолжается цепочкой `.pipe(...)`
  (`tap`, `catchError`). Адрес API задаётся в `environment.ts`.
- Обложки — локальные файлы (`public/images/covers/*.svg`); загруженные пользователем
  изображения хранятся в **IndexedDB** (ссылки вида `idb:<id>`, при недоступности — `mem:<id>`
  в памяти сессии).

## Запуск

Сначала запустите backend (см. корневой `README.md`), он слушает `http://localhost:5080`.
Затем:

```bash
npm install          # установка зависимостей
npm start            # dev-сервер, http://localhost:4200
npm run build        # production-сборка в dist/gametrack
npm test             # юнит-тесты (Karma/Jasmine)
```

Для тестов без watch-режима (CI):

```bash
npx ng test --watch=false --browsers=ChromeHeadless
```

Статус: production-сборка проходит без ошибок; **20 юнит-тестов — все зелёные**.

## Ограничения

- Backend использует in-memory хранилище: аккаунты и игры сбрасываются при перезапуске API.
- Регистрация настоящая (email + PBKDF2-хеш пароля), но хранилище живёт только в памяти.
- Профиль в демонстрационном приложении один: при входе под другим аккаунтом его имя и
  email обновляются. Библиотеки игр при этом разделены по аккаунтам: демо-профиль видит
  стартовые игры, каждый новый аккаунт начинает с пустого списка.
- Загруженные обложки хранятся только в браузере (IndexedDB) и не синхронизируются с сервером.
