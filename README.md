# GameTrack — трекер видеоигр

Одностраничное приложение (SPA) на **Angular 20** для ведения личной коллекции видеоигр.
Работает **полностью на фронтенде**: без бэкенда, без HTTP-запросов и без внешних сервисов
(Firebase/Supabase не используются). Все данные хранятся в браузере, доступ имитируется
мок-слоем с искусственной задержкой.

Весь интерфейс — на русском языке. Тёмная игровая тема: фон `#041629`, карточки
`#071F35` / `#0B2944`, акцент `#4C45FF`. Иконки — один набор **PrimeIcons**.

## Что реализовано

### Аутентификация
- Вход (`/auth/login`) с предзаполненными демо-данными `demo@gametrack.app` / `demo1234`.
  Подходит любой корректный email и непустой пароль.
- Восстановление пароля (`/auth/recovery`) в демонстрационном режиме (письмо не отправляется,
  запрос просто подтверждается на экране).
- Сессия сохраняется между перезагрузками. Выход — из меню профиля в шапке.
- Маршрутизация защищена: `authGuard` не пускает гостя в приложение (редирект на вход с
  `redirect`), `guestGuard` не пускает вошедшего пользователя на страницы входа.

### Дашборд (`/dashboard`)
- Приветствие по имени, краткая сводка (всего игр, в процессе, пройдено, хочу пройти),
  список недавних игр со ссылкой на полный список.

### Библиотека игр (`/games`)
- Сводка всех игр, объединённый поиск (по названию, жанру, платформе) и фильтр по статусу
  («Все», «В процессе», «Пройдено», «Хочу пройти», «Брошено»).
- Живой счётчик найденных игр и состояние «ничего не найдено».

### Карточка игры (`/games/:id`)
- Обложка, год выпуска, рейтинг, жанр, платформа, дата добавления, описание.
- Смена статуса, кнопка-переключатель «в список желаемого / убрать из желаемого»,
  кнопка «Отметить как пройденную», переход к редактированию.
- Удаление с подтверждением (диалог) и состояние «Игра не найдена» для некорректной ссылки.

### Добавление и редактирование (`/games/new`, `/games/:id/edit`)
- Валидируемая форма: название (уникальное), жанр, платформа, статус, год, рейтинг, описание.
- Загрузка обложки (файл изображения), превью, подстановка плейсхолдера при отсутствии картинки.

### Список желаемого (`/wishlist`)
- Формируется динамически из игр со статусом `want-to-play` (отдельного хранилища нет).
- Быстрые действия по каждой игре.

### Статистика (`/statistics`)
- Всего / пройдено / в процессе / хочу пройти / брошено, доля пройденных, средний рейтинг.
- Распределение по статусам, жанрам и платформам — пересчитывается автоматически при любом
  изменении библиотеки, без перезагрузки.

### Профиль (`/profile`)
- Просмотр и редактирование имени, email, аватара; персональная статистика и любимые жанры/платформа.
- Изменения сразу отражаются в шапке и на всех экранах (единый источник состояния — сигналы).

### Общее
- Уведомления-тосты о результате действий.
- Адаптивная вёрстка: на узких экранах боковое меню превращается в выдвижную панель
  (кнопка-гамбургер), проверено на ширине 390 px.
- Мок-слой имитирует задержку сети 300–600 мс, поддерживает восстановление при повреждённых
  данных и понятные ошибки.

## Архитектура

```
src/app
├── core/
│   ├── config/         конфигурация приложения и маршрутов (lazy-loading)
│   ├── navigation/     guards: authGuard / guestGuard
│   └── services/       GamesService, StatisticsService, AuthService,
│                       ProfileService, ImageStoreService (IndexedDB)
├── mock/               имитация бэкенда
│   ├── seed.ts         стартовые данные (7 игр + профиль)
│   ├── mock-db.ts      «БД» в localStorage (gametrack.db.v1) с валидацией и восстановлением
│   ├── mock-api-client.ts  центральная обёртка запроса: задержка 300–600 мс, персистентность
│   ├── games/ auth/ profile/   доменные обработчики операций
│   └── mock-error.ts   типизированные ошибки
├── shared/             переиспользуемый слой
│   ├── components/     game-card, cover-image, status-pill, confirm-dialog,
│   │                   empty-state, toast-host
│   ├── models/ constants/ utils/ validators/
│   └── notifications/  сервис тостов
├── layout/             app-shell (сайдбар + шапка), guest-shell, not-found, app-root
└── features/           страницы по фичам: auth, dashboard, games, wishlist,
                        statistics, profile — каждая со своими *.routes.ts
```

Ключевые решения:
- **Standalone-компоненты** + Angular Router, строгий TypeScript (`strict`), SCSS, lazy-loaded
  маршруты фич.
- **Signals** как единый источник истины: сервисы хранят состояние в сигналах, все экраны
  обновляются реактивно, без перезагрузки и без дублирования данных.
- Единственная точка хранения — `mock-db`; вся логика фильтрации вынесена в
  `shared/utils/game-filter.ts` и переиспользуется и мок-обработчиком, и клиентом.
- Обложки — только локальные файлы (`public/images/covers/*.svg`), загруженные пользователем
  изображения хранятся в **IndexedDB** (ссылки вида `idb:<id>`, при недоступности — `mem:<id>`
  в памяти сессии). Битых картинок нет — есть плейсхолдер.

## Запуск

```bash
npm install          # установка зависимостей
npm start            # dev-сервер, http://localhost:4200
npm run build        # production-сборка в dist/gametrack
npm test             # юнит-тесты (Karma/Jasmine)
```

Для тестов без watch-режима (CI):

```bash
npx ng test --watch=false --browsers=ChromeHeadless
```

Статус: production-сборка проходит без ошибок; **23 юнит-теста — все зелёные**.

## Ограничения мок-слоя

- Данные живут **только в текущем браузере** (localStorage + IndexedDB). Очистка данных
  сайта сбрасывает библиотеку к стартовому набору из `seed.ts`.
- Нет реальной сети и сервера: задержка, ошибки и «письмо восстановления» — имитация.
- Авторизация демонстрационная: подходит любой корректный email и непустой пароль.
- Загруженные обложки не переживают очистку IndexedDB/хранилища браузера.
- Приложение однопользовательское: отдельные аккаунты и разграничение прав не моделируются.
